# Выводы и сравнение

| Подход            | Время, с | Ускорение |
|-------------------|---------:|----------:|
| sequential        |    2.491 | 1.00× |

**Задача 2 (I/O-bound, 12 страниц, 4 воркера):**

| Подход            | Время, с | Ускорение |

| sequential        |   17.202 | 1.00× |

## Главный вывод

Результат прямо противоположен в двух задачах — и это самое важное наблюдение:

| Тип нагрузки         | Лучший подход     | Почему |
|----------------------|-------------------|--------|
| **CPU-bound** (Задача 1) | `multiprocessing` | обходит GIL, грузит все ядра; потоки и async упираются в GIL |
| **I/O-bound** (Задача 2) | `asyncio` (и `threading`) | GIL освобождается на время ожидания сети; процессы избыточны |

## Объяснение через GIL

- **GIL** разрешает исполнять байткод Python только одному потоку одновременно.
- Для **вычислений** это значит, что несколько потоков не считают быстрее одного,
  а `asyncio` (один поток) тем более. Помогает только запуск **отдельных
  процессов**, у каждого свой интерпретатор и свой GIL.
- Для **ввода-вывода** поток, ожидающий ответ сети, отдаёт GIL другим — поэтому
  и потоки, и кооперативные корутины `asyncio` дают конкурентность без отдельных
  процессов. `asyncio` при этом самый лёгкий: нет накладных расходов на потоки и
  переключение контекста ОС.

## Когда что выбирать

- **Тяжёлые вычисления** (обработка чисел, изображений, ML-препроцессинг) →
  `multiprocessing` / пул процессов.
- **Много сетевых запросов / запросов к БД / работы с диском** → `asyncio`
  (если библиотеки асинхронные) либо `threading`.
- **Смешанная нагрузка** → комбинируют: например, async-цикл событий + пул
  процессов через `loop.run_in_executor(ProcessPoolExecutor(), ...)`.

## Замечания по реализации

- На macOS `multiprocessing` использует метод **spawn**, поэтому worker-функции
  вынесены на верхний уровень модуля, а запуск защищён `if __name__ == "__main__"`.
- В async-парсере запись в БД (синхронный psycopg2) вынесена в пул потоков через
  `asyncio.to_thread`, чтобы не блокировать цикл событий.
- aiohttp на macOS требует явного SSL-контекста из `certifi`.
- Подключение к БД открывается заново на каждое сохранение — это безопасно для
  всех трёх подходов (соединение нельзя разделять между процессами).
