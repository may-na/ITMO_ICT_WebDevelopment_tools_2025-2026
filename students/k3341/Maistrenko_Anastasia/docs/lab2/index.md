## Теория кратко

| Подход            | Что это                                              | Параллелизм | Когда полезен |
|-------------------|------------------------------------------------------|-------------|---------------|
| `threading`       | несколько потоков в одном процессе                   | ограничен GIL (одновременно работает 1 поток с байткодом) | I/O-bound |
| `multiprocessing` | несколько процессов, у каждого свой интерпретатор и GIL | настоящий, на разных ядрах | CPU-bound |
| `asyncio`         | кооперативная многозадачность в одном потоке          | нет (но эффективное переключение на ожидании I/O) | I/O-bound |

**GIL (Global Interpreter Lock)** — глобальная блокировка интерпретатора CPython:
в каждый момент времени байткод Python исполняет только один поток. Поэтому:

- для **CPU-bound** задач (чистые вычисления) потоки и async **не** ускоряют
  работу — нужен `multiprocessing`, который обходит GIL за счёт отдельных
  процессов;
- для **I/O-bound** задач (сеть, диск) GIL освобождается на время ожидания,
  поэтому отлично работают и потоки, и `asyncio`.

Эти два сценария проверяются в двух задачах ЛР.

## Как запустить

```bash
cd Lr2/code
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Задача 1
python task1_sum/benchmark.py --n 100000000 --workers 8

# Задача 2 (нужна БД из ЛР1; настройки в .env)
python task2_scraping/benchmark.py --workers 4
```
