# Эндпоинты API

Полный список маршрутов приложения. Все эндпоinты (кроме регистрации, входа и
корневого) требуют JWT-токен и работают только с данными текущего пользователя.
Интерактивно всё доступно в Swagger UI: `/docs`.

## Аутентификация — `/auth`

| Метод | Путь                | Назначение                         |
|-------|---------------------|------------------------------------|
| POST  | `/auth/register`    | регистрация                        |
| POST  | `/auth/token`       | вход, получение JWT                |
| GET   | `/auth/me`          | текущий пользователь               |
| GET   | `/auth/users`       | список пользователей               |
| PATCH | `/auth/me/password` | смена пароля                       |

Подробнее — [Аутентификация (JWT)](auth.md).

## Счета — `/accounts`

| Метод  | Путь                   | Возвращает                              |
|--------|------------------------|-----------------------------------------|
| GET    | `/accounts`            | список счетов                           |
| POST   | `/accounts`            | созданный счёт                          |
| GET    | `/accounts/{id}`       | счёт **со вложенным списком транзакций** |
| PATCH  | `/accounts/{id}`       | обновлённый счёт                        |
| DELETE | `/accounts/{id}`       | `204`, каскадно удаляет транзакции      |

## Транзакции — `/transactions`

| Метод  | Путь                                       | Назначение                                   |
|--------|--------------------------------------------|----------------------------------------------|
| GET    | `/transactions?account_id=&category_id=`   | список (с фильтрами), вложенные объекты       |
| POST   | `/transactions`                            | создать (теги + пересчёт баланса счёта)       |
| GET    | `/transactions/{id}`                       | транзакция со счётом, категорией, тегами      |
| PATCH  | `/transactions/{id}`                       | обновить (с корректным пересчётом баланса)    |
| DELETE | `/transactions/{id}`                       | удалить (баланс восстанавливается)            |
| POST   | `/transactions/{id}/tags/{tag_id}`         | привязать тег (M:M)                           |
| DELETE | `/transactions/{id}/tags/{tag_id}`         | отвязать тег                                  |

**Пример ответа** `POST /transactions` (видны вложенные `account`, `category`,
`tags`; баланс счёта пересчитан 1000 → 749.5):

```json
{
  "amount": 250.5, "type": "expense", "description": "Пятёрочка",
  "id": 1, "user_id": 1, "account_id": 1, "category_id": 1,
  "account":  {"id": 1, "name": "Карта Тинькофф", "balance": 749.5, "currency": "RUB"},
  "category": {"id": 1, "name": "Продукты", "type": "expense", "icon": "🍎"},
  "tags":     [{"id": 1, "name": "важное", "color": "red"}]
}
```

!!! warning "Валидация: достаточность средств"
    Сумма операции всегда `> 0` (проверяется схемой). Дополнительно при создании
    и изменении расхода/перевода проверяется, что на счёте **хватает средств** —
    иначе возвращается `400 Bad Request` и операция не выполняется:

    ```json
    // POST /transactions  {"amount": 250, "type": "expense", ...}  при балансе 100
    {"detail": "Недостаточно средств на счёте «Карта»: баланс 100.0, требуется 250.0"}
    ```

    Доходы (`income`) такой проверке не подлежат — они только увеличивают баланс.

## Бюджеты — `/budgets`

| Метод  | Путь                                          | Назначение                                          |
|--------|-----------------------------------------------|-----------------------------------------------------|
| GET    | `/budgets`                                     | список бюджетов                                     |
| POST   | `/budgets`                                     | создать бюджет                                      |
| GET    | `/budgets/{id}`                                | бюджет **с распределением по категориям и лимитами** |
| PATCH  | `/budgets/{id}`                                | обновить бюджет                                     |
| DELETE | `/budgets/{id}`                                | удалить бюджет и его связи                          |
| POST   | `/budgets/{id}/categories`                     | привязать категорию с `planned_limit`               |
| PATCH  | `/budgets/{id}/categories/{category_id}`       | изменить `planned_limit`                            |
| DELETE | `/budgets/{id}/categories/{category_id}`       | отвязать категорию                                  |

**Пример ответа** `POST /budgets/{id}/categories` — ассоциативное поле
`planned_limit` приходит вложенным вместе с категорией:

```json
{
  "id": 1, "name": "Бюджет на июнь", "limit_amount": 50000.0, "period": "month",
  "allocations": [
    {"category": {"id": 1, "name": "Продукты", "type": "expense"}, "planned_limit": 15000.0}
  ]
}
```
